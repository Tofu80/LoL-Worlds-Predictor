# LoL Worlds Predictor

Predicts title odds for League of Legends Worlds 2026. It rates teams with Elo, then runs a Monte Carlo
simulation of the Swiss Stage and knockouts. The model is backtested on Worlds 2023–2025.

This is a portfolio project. The modelling decisions belong to the owner (Phu). When a choice affects
the model (constants, formulas, data filters), propose it and explain the trade-off. Don't pick one silently.

## Hard rules

1. **No look-ahead leakage.** To predict a game played at time t, use only games with `date < t`.
   Ratings start from games before the tournament's start date (`cutoff_date`) and update game by
   game during the tournament: predict a game first, then add its result. Ratings, decay weights and
   any normalisation all follow this rule. Every backtest function takes an explicit `cutoff_date`.
   If you can't prove a feature respects the cutoff, flag it. (`rating_updates: frozen` in
   `config/backtest.yaml` keeps ratings fixed at the start date instead.)
2. **`data/raw/` is read-only.** All cleaning happens in code that writes to `data/processed/`.
3. **Constants live in `config/`.** These include the Elo K-factor, initial rating, decay half-life
   (default 182 days), simulation count (default 10,000), rating noise and the random seed.
4. **Simulations are reproducible.** Use a seeded `numpy.random.Generator` that's passed in, never
   global random state.
5. **Don't change a test to make it pass.** If a test looks wrong, say so and ask.

## Data notes (Oracle's Elixir)

- Each game has 12 rows: 10 player rows and 2 team rows (`position == "team"`). Team-level
  modelling uses only the team rows. Key columns: `gameid`, `league`, `date`, `side`, `teamname`, `result`, `patch`.
- Check `datacompleteness`. Some leagues (notably LPL) have partial data. Results are usually still
  usable even when detailed stats aren't.
- Team names change between seasons (rebrands, sponsor names). Keep the mapping in a single
  alias table in `config/`, not scattered string fixes.
- Cross-region strength comes only from international events (MSI, Worlds, other inter-league events).
  Keep this in mind for any Elo change, because regional ratings float otherwise.
- Riot API (solo queue) is optional and has no LPL coverage, so it can't be a required input.

## Model (current scope)

- **Team Elo** with exponential time decay (6-month half-life, configurable).
- **Per-game probability is constant within a series** for now. Series probabilities:
  Bo3 = p²(3 − 2p), Bo5 = p³(10 − 15p + 6p²). These are tested against brute-force enumeration.
- **Simulation:** about 10,000 runs, with noise added to ratings each run to reflect rating uncertainty.
- **Tournament format** (Swiss rules, which matches are Bo1/Bo3, seeding, bracket) lives in
  `config/worlds_<year>.yaml`. Check it against the official rules. Don't assume it from memory.

**Parked, don't build yet:** Fearless draft effects (late-game shrink toward 50%, game number vs.
series score), player-level ratings, roster-change adjustments. If a change starts to need one of
these, stop and raise it.

## Evaluation

- Backtest on Worlds 2023, 2024 and 2025. The main metric is log loss. Also report Brier score and a
  calibration table.
- Betting odds comparison: remove the bookmaker margin first (normalise implied probabilities to
  sum to 1), then compare log loss on the same set of matches.
- A model change is "better" only if backtest log loss improves. Record the before/after numbers in
  `docs/decisions.md`.

## Invariants worth testing

- Simulated title odds sum to 1 (within floating-point tolerance).
- In the Swiss Stage, no two teams meet twice, and each team stops at 3 wins or 3 losses.
- Elo is zero-sum per game. A 50/50 match moves both teams by exactly K/2.
- Series probability is monotonic in p and equals 0.5 when p = 0.5.

## How to work in this repo

- For anything beyond a small fix, use plan mode. Read the relevant code, propose a plan and wait
  for approval.
- **Every new feature gets its own branch.** Branch off `main`, implement and test there, then push
  the branch and open a pull request (`gh pr create`). Merge it on GitHub only after all tests pass
  (`pytest` clean, `ruff` clean). `main` is protected on GitHub: no direct pushes, force-pushes or
  deletion. Never develop directly on `main`.
- Run the `leakage-reviewer` agent (`.claude/agents/leakage-reviewer.md`) before every
  `gh pr create`. Every finding must be either fixed (with a test) or listed in the PR description
  as an open decision (severity, what, options). None may be silently skipped.
- A security review runs once per PR: a project hook in `.claude/settings.json` fires after a
  successful `gh pr create` and tells Claude to run `/security-review` and post the result as a PR comment.
- Write tests first for logic with known right answers (Elo, series maths, Swiss rules).
- Keep changes small and commit-sized. Commit messages say *why*, not just what.
- Log modelling decisions in `docs/decisions.md` with the date, decision, alternatives and evidence.
- Python 3.10+, type hints on public functions, pandas/numpy. Don't add new dependencies without asking.
